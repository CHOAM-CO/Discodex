# 사용자 실사용 확인

아래 항목은 설치본에서 사용자가 직접 확인할 수동 점검 항목이다. 이 문서는 음성 동작이 검증됐다고 주장하지 않으며 자동 시험 절차나 별도 수집기를 정의하지 않는다. 결과는 관찰한 동작과 실제 Discord/native 응답으로 기록한다.

- 프로필 이름이 텍스트와 음성에서 같은 AI 동료 정체성으로 유지되는지 확인한다. 음성이 Codex를 자기 이름으로 소개하지 않는지, 별도 voice prompt가 적용되는지 확인한다. 서비스 재시작 뒤에도 같은 대화 이력을 이어야 한다.
- 홈 채널의 Discord 조작자 입력이 같은 지속 Codex thread로 전달되고 홈 채널의 원 메시지에 답장되는지 확인한다.
- Codex가 질문을 반환할 때 Discord 폼 입력이 해당 native 요청에 반영되는지, 승인/거절 선택이 해당 요청의 결과와 맞는지 확인한다.
- `/discodex models`, `/discodex permission-profiles`의 실제 목록과 `/discodex model`, `effort`, `fast`, `permissions` 변경 응답을 확인한다. 기본값과 진행 중 turn의 적용 상태가 분리되어 안내되는지 살핀다.
- 허용된 음성 채널에서 연결 준비 후 입장하고, 자동 인사 없이 사용자의 첫 발화를 기다리는지 확인한다. 첫 발화 지연과 음성 끊김은 직접 관찰한다.
- 전사가 완료된 단위로 게시되고, `확정` 표시 없이 에이전트 이름과 실제 Discord 서버 닉네임으로 표시되는지 확인한다. 서버 닉네임이 없으면 Discord 표시 이름, 사용자명 순으로 사용한다.
- 통화를 종료하고 다시 연결했을 때 각 통화의 새 Discord 전사 스레드에 게시되는지 확인한다. 늦게 도착한 이전 통화 전사는 이전 스레드에 남고, Codex 대화 문맥은 유지되어야 한다. 재연결 뒤에도 자동 인사 없이 사용자의 발화를 기다리고, 이전 통화의 종료 결과를 현재 상태로 착각하지 않는지 확인한다.
- 기존 ad-hoc 설치에서 고정 서명으로 최초 전환한 뒤 필요하면 권한을 허용하고, 이후 같은 서명으로 업데이트할 때 기존 권한이 유지되는지 확인한다. 키체인 인증이 필요하면 설치기가 요청한 macOS 대화상자에서 직접 허용한다.
- Mac 신규·재설치 또는 ad-hoc 서명 전환 시, 서비스 시작 전에 전체 디스크 접근 설정 화면과 실제 설치 파일이 열리는지 확인한다. 필요한 권한을 사용자가 켜고 계속해야 하며, 취소하면 서비스 시작을 진행하지 않아야 한다. 같은 서명 업데이트에서는 이 안내를 반복하지 않는다.
- 현재 통화를 끝내려는 뜻으로 “나가봐”, “종료해도 돼” 또는 문맥상 분명한 “나중에 다시 보자”라고 했을 때 실제로 채널에서 나가는지 확인한다. 음성 응답만으로 성공을 판단하지 않고, 작업 모델의 voice_leave 호출과 실제 퇴장 결과를 확인한다. 음성 종료 도구가 이번 통화의 요약을 작성해 전사 정리가 끝난 뒤 해당 통화의 스레드 생성 글을 수정하는지 확인한다. 수동 `/discodex voice-leave`에는 요약이 없고, 이미 끝난 통화의 종료 도구를 반복 호출해도 이전 원글이 다시 수정되지 않아야 한다. `전사 처리: 완료` 표시는 나타나지 않아야 한다. 인용·부정·다른 작업의 종료는 문맥에 맞게 구분해야 한다. 다시 연결하면 이전 대화 문맥을 이어야 한다.
- 일반 채팅을 보낸 뒤 Codex가 처리하는 동안 홈 채널의 입력 중 표시가 유지되고, 최종 응답·오류·연결 종료 뒤 사라지는지 확인한다. 비공개 ‘생각 중’ 표시는 slash 명령 같은 상호작용 응답에서만 사용할 수 있다.
- 재시작 후 같은 thread가 유지되는지 확인한다. 설치·제거는 테스트 전후 소유 서비스·경로를 사용자가 확인한다.

검증 중 자격증명이나 비공개 대화 내용을 문서에 복사하지 않는다. 확인하지 못한 항목은 미완료로 남긴다.

- 음성 통화 중 홈채널 메시지와 다른 채널 멘션이 통화를 방해하지 않고 대기하는지 확인한다. 현재 전사 스레드의 텍스트는 멘션 없이 같은 통화로 전달되어야 한다. 통화가 끝나면 대기 메시지와 첨부를 순서대로 처리하고 일반 답변은 홈채널에 남아야 한다. 연결 준비·종료 중 입력, 연속 재통화, 대기 중 워커 재시작에서도 누락·중복·다른 통화로 전달이 없는지 확인한다. 전사 스레드의 첨부는 홈채널 입력 안내를 표시해야 한다.


Discord 도구 추가분도 사용자가 직접 확인한다.

- 홈 채널 밖에서 봇을 멘션하고, 일반 응답·질문·승인·처리 상태는 홈 채널에만 남으며 원 메시지의 출처 링크가 맞는지 확인한다. 다른 채널에 잘못된 Discord 답장 참조를 만들거나 자동 답장을 남기면 안 된다.
- 직접 보낸 이미지·일반 파일을 세션에서 사용하는지, 대기 입력으로 보낸 첨부가 재시작 뒤에도 연결되는지 확인한다.
- 채널·사용자 조회, 이름 변경 후 조회, 중복 이름 후보 선택을 확인한다. 오래된 선택을 다른 대상으로 바꾸어 실행하면 안 된다.
- 다른 채널에서 해당 채널로 요약을 발송해 달라고 명시적으로 요청하고, `discord_send_message`의 결과로 실제 발송 여부를 판단하는지 확인한다. 일반 답변만 작성하면 홈 채널에만 남아야 하며, 별도 발송의 멘션은 목록에 지정한 사용자로 제한되어야 한다.
- Discord 메시지 링크 커서로 이어 읽는 동안 새 메시지를 추가해도 같은 기준 이전의 기록을 읽는지 확인한다. `offset: 10`은 최신 10개를 건너뛰어야 한다.
- 메시지 조회·검색에서는 첨부 이름·확장자만 표시되고 파일이 다운로드되지 않는지, 메시지 링크와 파일명으로 요청한 첨부만 내려받고, 같은 이름의 파일이 여럿이면 후보 선택을 요구하는지 확인한다.
- 검색 기본 범위 100개와 최대 1000개, 권한 없는 채널·서버 멤버 조회 실패의 안내를 확인한다.

- Windows 설치 시 같은 사용자로 UAC를 승인한 뒤 관리자 권한 자동 시작이 등록되는지 확인한다. 취소·다른 관리자 계정 인증 시 기존 작업을 변경하지 않아야 한다. 업데이트·제거는 해당 설치의 작업만 처리해야 한다. 실제 프로그램 설치 중 추가 UAC 여부는 사용자가 확인한다.

- Discord 전달 기능으로 이미지가 포함된 메시지를 봇의 홈 채널에 보내고 이미지와 전달 본문을 함께 읽는지 확인한다. 홈 입력에는 작성자와 본문만, 다른 채널 입력에는 서버·채널 이름이 포함되어야 한다. 메시지 기록의 전달 첨부를 이름과 Discord 메시지 링크로 내려받을 수 있는지도 확인한다.

- MCP 도구 실행 승인에서는 JSON 응답 폼 대신 이번만 허용·거절·취소가 표시되는지 확인한다. 세션 허용·항상 허용은 native가 해당 범위를 제시했을 때만 표시되어야 한다. 일반 추가 정보 요청은 입력 폼으로 남아야 한다. 워커 재시작 전의 승인 카드는 만료되므로 해당 작업을 다시 요청해 새 카드로 확인한다.
