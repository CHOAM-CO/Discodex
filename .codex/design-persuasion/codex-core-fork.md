# Discodex 관리형 코어와 하네스의 책임

수정일: 2026-10-23 (Asia/Seoul)  
기준 릴리스 버전: `v1.2.0` (`2026-10-23T10:00:48Z` 정식 `latest` 공개 완료).

`v1.2.0` 구현 당시에는 비공식 배포 검증 단계에서 기록 투영 지연을 수정하고 설계 재검토와 GPT-6.1 Sol 코드 리뷰를 거쳐 세 운영체제의 지정된 환경에 적용했으며, 그 검증 이력은 아래 검토·설치 기록에 보존되어 있다. 정식 공개가 완료된 고정 태그 `v1.2.0`의 런타임·릴리스 산출물은 변경하지 않으며, 후속 데스크톱 앱 및 내장 설치기 확장은 아래 기반 계약을 유지한 채 별도 마일스톤으로 추진한다.

## 이 문서와 컨텍스트 설계의 역할

이 문서는 관리형 Codex 코어, AGY CLI, 데이터·설정의 소유 범위와 유지할 기존 기능을 설명한다. 이번 음성·서브에이전트·AGY 대화 변경의 계약과 완료 기준은 [음성·에이전트 컨텍스트 설계](voice-and-agent-context-2026-10-23.md)에서 정의한다. `v1.2.0` 이후 후속 마일스톤으로 추진하는 macOS·Windows·Linux 데스크톱 앱, 창 닫기 후 백그라운드 서비스 유지, 무터미널(Zero-Terminal) 내장 설치기 및 macOS `Discodex` 전체 디스크 접근 권한(Full Disk Access) 안내에 대해서는 [제품 기획서](../planning/product-plan.md)가 사용자 여정·기능 대응·예외 처리 범위를 정의하고, [데스크톱 앱 설계설득](desktop-app.md)이 상위 확정 결정(`D24`–`D28`)과 아키텍처 결정 트리(`G1`–`G7`)를 다룬다.

1.0 최초 설계는 [1차 검토에 보존한 원본](reviews/2026-10-23/round-01/core-design.input.md)에서 볼 수 있다. 그 원본의 버전·조사 결과·보류·미구현 표시는 당시 이력이다. 현재 작업은 아래 기반과 컨텍스트 설계의 최신 결정을 따른다.

질문 카드는 답변을 저장하면 즉시 선택 버튼을 제거하고 선택한 답변과 제출 진행 상태를 표시한다. 큐 대기와 하네스 수신 확인 대기를 구분해 표시하며, 하네스가 접수하면 대기 표시를 마치고 답변을 남긴다. 전달이 거절되거나 실패하면 오류를 표시하고 재시도할 선택 화면을 복구한다. 이 상태 전이는 [질문 전달 처리](../../src/async_questions.rs)의 기존 동작을 따른다.

프로필에 승인 정책이 없으면 Discodex는 on-request를 사용하고, 저장된 명시적 선택이 있으면 그 값을 사용한다. 사용자가 정책을 바꾸면 [native 설정 처리](../../src/native.rs)는 thread/settings/update로 적용하고 알림 또는 세션 재조회에서 실효값을 확인한 뒤 프로필에 저장한다.

기존 업데이트 진입점은 내려받은 새 워커의 update-helper에서 install::update로 연결된다. [런타임 설치](../../src/install/runtime.rs)는 워커 버전과 코어 SHA에 맞는 manifest와 빌드된 archive를 확인해 버전별 디렉터리에 배치한다. 이번 비공식 설치에서는 변경한 워커·코어를 빌드해 소유 런타임 구조에 복사하고 변경하지 않은 helper를 재사용한다.

변경 전 [AGY 어댑터](../../src/native_external.rs)는 외부 실행 요청마다 CLI 세션을 만들고 전체 native history를 한 사용자 메시지로 보냈다. 이번 구현은 컨텍스트 설계 G3에 따라 같은 AGY conversation을 재개하고 새 입력을 전달한다. 설치 검증에서 확인한 과거 도구 기록의 반복 스캔은 G4의 순차 투영과 체크포인트 버전 처리로 수정한다.

## 하네스와 모델의 책임

| 주체 | 맡는 일 |
|---|---|
| Discodex | Discord 채널·스레드·DM·음성 연결, 메시지와 첨부 전달, 설정 UI, 소유 런타임의 설치·업데이트를 처리한다. |
| Codex app-server | Discodex에 thread·turn·도구·히스토리·realtime RPC와 이벤트를 제공한다. |
| Codex core | Codex Session과 작업·자식 수명을 관리한다. Codex executor에서는 요청 컨텍스트·모델 API 호출·도구 실행·결과 기록·후속 요청을 처리한다. AGY executor에서는 외부 하네스 연결로 작업을 전달한다. |
| Discodex AGY 어댑터 | app-server 외부 실행 계약과 AGY CLI의 입력·출력 프로토콜을 연결한다. 모델 ID와 effort를 나눠 전달하고 각 외부 실행의 Codex 작업 식별자와 AGY 이벤트를 연결한다. conversation 대응과 새 입력 전달은 컨텍스트 설계 G3을 따른다. |
| AGY CLI | 자기 conversation과 모델 요청·내장 도구 실행 루프를 관리한다. Codex 전용 기능은 연결된 MCP 도구로 호출한다. |
| 모델 API | Codex core는 OpenAI·로컬·등록 공급자의 모델 API를 호출하고, AGY CLI는 AGY 서비스 모델을 호출한다. 모델은 텍스트·도구명·인자를 생성하고 각 하네스가 자기 모델의 응답을 처리하며 도구를 실행한다. |

Codex core의 threadId와 AGY CLI의 conversation_id는 별도 세션 식별자다. turnId와 runId는 해당 작업·외부 실행을 식별한다. AGY 어댑터가 유지할 세션 대응과 재시작 시 복원 방식은 컨텍스트 설계 G3에서 정한다.

OpenAI 모델과 로컬·다른 공급자 모델은 Codex 하네스의 API 호출 대상이다. AGY CLI는 이 모델 API들과 다른 계층의 하네스다. AGY의 일반 내장 도구는 유지하고, 부족한 Codex·Discodex 기능과 Codex 서브에이전트 관리를 MCP로 연결한다. 관리형 AGY 자체의 위임 도구는 기존 사용자 결정대로 공식 hook으로 중지하며 정확한 도구 목록과 적용 범위는 컨텍스트 설계 G4에 적는다.

## 데이터와 설정을 보존하는 범위

실행 파일과 Codex 데이터 위치는 별개다. 같은 Codex home을 선택하면 설정·인증·메모리·히스토리의 기존 저장 경로를 사용한다. 데이터는 파일·SQLite·OS 자격 증명 저장소 등으로 나뉘어 저장되므로, Discodex는 DB 파일 하나만 공유하는 방식으로 전체 데이터 공유를 대신하지 않는다.

기록 조회용 투영 캐시는 기존 SQLite와 체크포인트를 사용한다. 포크는 투영 버전 열을 추가하는 migration에 `202610230001_discodex_external_tool_projection`처럼 소유자를 표시한 timestamp 번호를 사용한다. 기존 migration의 번호와 checksum은 유지한다. 공식판 Codex가 포크 migration이 적용된 공유 DB를 열 때, 현재 공식 SQLx 실행기는 자기 바이너리에 없는 기적용 migration 번호를 허용한다. 자기 목록에 있는 migration의 checksum 검증은 유지하며, 미적용 상태인 후속 공식 migration도 실행한다. 업스트림을 병합할 때는 포크 번호와 새 공식 번호의 충돌 여부를 확인한다.

Discord 설정 UI에서 바꾼 값은 해당 Discodex 프로필에 저장하고 실행 인자나 지원되는 thread 설정으로 적용한다. 공유 Codex 설정 파일과 개인 AGY 설정 파일은 UI 변경 때문에 덮어쓰지 않는다. 메모리·도구가 사용자의 요청으로 선택한 파일이나 공유 기록을 갱신하는 동작은 해당 하네스의 기존 경로를 따른다.

서로 다른 세션은 같은 Codex home의 데이터 위치를 공유할 수 있으며, 같은 세션은 동시에 한 프로세스만 실행한다. 실행 파일을 이전 버전으로 복구할 때 Discodex는 파일 교체 결과와 Codex의 데이터 읽기·마이그레이션 결과를 각각 보고한다. 기존 데이터 파일과 DB 형식은 해당 Codex 버전의 호환 계약을 따른다. 런타임 제거는 소유권이 확인된 자원만 대상으로 한다.

## API 공급자 변경과 하네스 변경

| 변경 | 유지하거나 바꿀 동작 |
|---|---|
| Codex 하네스 안의 API provider 변경 | 기존 thread/fork 경로로 기록을 이어받는 새 Session을 만들고 모델·공급자 설정, 토큰 계산·압축, encrypted_content 전송 호환을 유지한다. core는 요청 복사본에서 공급자가 읽을 수 없는 암호화 항목을 읽기 불가 표시로 바꾸고 해당 건수를 로컬 진단 로그에 남긴다. 원본 히스토리는 보존한다. |
| Codex↔AGY 하네스 변경 | 컨텍스트 설계 G1에 따라 새 작업 세션으로 시작하고 이전 대화를 자동 이관하지 않는다. 기존 기록은 보존하고 필요할 때 조회할 참조를 제공한다. |
| 같은 AGY 작업의 후속 입력 | 컨텍스트 설계 G3에 따라 같은 AGY conversation에 새 입력을 보낸다. 매 실행에서 공식 대화 ID 재개 계약을 사용한다. 전체 native history JSON을 다시 입력하지 않는다. |

Codex의 provider 전송 호환 처리는 [provider_history](../../third_party/codex/codex-rs/protocol/src/provider_history.rs)와 기존 코어 요청 경로를 사용한다. 메모리·이전 대화·부모 대화의 조회 표현과 세션 참조는 컨텍스트 설계가 정의한다.

음성 모델은 메인 하네스와 무관하게 OpenAI GPT Live를 사용한다. GPT Live는 통화 시작에 연결한 Codex Session(`T0`)으로 작업을 위임하고, core는 `T0`의 executor와 provider 설정으로 작업을 보낸다. 통화 중 primary가 `Tnew`로 바뀌어도 이 통화의 위임 대상은 `T0`로 유지한다. AGY를 메인으로 선택한 상태의 GPT Live 음성도 이번 범위다. AGY 자체 음성 API 연결은 포함하지 않는다. 음성 원본 기록, 모델용 위임 입력·종료 전사 전달, 도구 결과의 기록과 조회는 컨텍스트 설계 G2~G4에서 다룬다.

## 기본 지침과 설명 문체

현재 Discodex의 [기본 지침 구성](../../src/instructions.rs)은 [프로필 지침 리소스](../../resources/messages/native.json)를 baseInstructions로 전달해 모델 카탈로그의 기본 본문을 대체한다. developer 지침과 실제 도구·승인 규칙은 core의 별도 경로로 적용된다. 공통 본문에는 실패·미완료와 추정을 알리는 지침이 있지만, 매 설명에 승인 여부를 환기하라는 규칙은 없다.

이번 변경은 baseInstructions가 모델 카탈로그의 기본 본문을 대체할 때 빠지는 설명 문체 기준을 네 언어의 프로필 지침에 명시한다. 에이전트는 행동 주체·조건·결과를 직접 설명하고, 실패 원인이나 확인이 필요한 범위는 해당 사실을 설명하는 문장에서 구체적으로 밝힌다. 반복적인 승인 상태 환기, 불필요한 경고와 면책, 요청하지 않은 대조 설명을 덧붙이지 않는다. 기존 도구·권한·프로젝트 규칙은 유지한다.

## 이번 변경의 완료 기준과 진행 순서

현재 컨텍스트 설계가 세션·기록·모델 입력의 계약을 소유한다. 코어와 Discodex(어댑터·MCP 포함)의 변경은 다음 기존 기능을 보존해야 한다.

1. AGY의 대화 유지와 하네스 전환이 컨텍스트 설계 G1·G3의 경계를 따른다. 모델명 문자열로 실행기나 공급자를 추측하지 않고 저장된 선택과 실제 프로토콜을 사용한다.
2. 기존 메모리·히스토리·인증·프로필 설정과 소유권 기록을 보존한다. 새 세션을 시작해도 과거 기록은 조회할 수 있다.
3. Codex API provider 전환의 암호화 전송 호환과 기존 자식 관리·설정 상속을 유지한다. AGY CLI의 내부 모델 루프를 Discodex에서 다시 구현하지 않는다.
4. Discodex는 Codex core·app-server·AGY CLI와 자체 어댑터·MCP 처리기에서 발생한 실패를 해당 요청에 연결해 원래 오류 메시지·코드·상태와 함께 Discord로 전달한다. 원인을 특정할 근거가 없으면 확인한 오류만 알린다. Discord 전달 자체가 실패하면 Discodex는 구체적인 전달 오류를 기존 로컬 진단에 남긴다. 진단에서 실제 비밀값만 가린다.
5. 질문 완료 표시, 승인 정책, 모델·effort 분리, 전용 AGY MCP, 네 언어 UI와 모든 설정 페이지의 나가기 동작을 유지한다.

이번 지연 수정은 설계 수정 → 같은 기준의 독립 기술·문서·Gemini 한국어 재검토 → 구현 → GPT-6.1 Sol 코드 리뷰 → 필요한 빌드 → 지정된 Windows·macOS·Ubuntu 환경의 비공식 설치 순서로 진행한다. 이번 작업에서는 자동화 테스트·새 테스트 실행기·반복 모델 probe를 실행하지 않는다. 사용자의 음성 시험과 허용된 수동 CUA 결과를 각각 기록한다.

대상 환경에는 빌드한 워커와 코어 산출물을 설치하며, 후속 수정에서 코어가 바뀌지 않은 경우에만 코어 재빌드를 생략한다. 정식 릴리스 공개는 이번 비공식 설치와 별도다. 구체적인 설치·보존 확인은 [검토 기록](reviews/2026-10-23/README.md)에서 관리한다.
