Discodexは1つのDiscordアプリプロファイルを1つの永続会話に接続します。テキストと音声はCodexの文脈を共有し、任意でAntigravity CLIをテキスト会話に利用できます。ネイティブタスクとサブエージェントの管理は同梱Codexフォークが担当します。

本ページは1.0のソースに対応しています。ダウンロード可能なバイナリは公開済みReleaseのタグに従います。

## 主な機能

| 機能 | 説明 |
| --- | --- |
| 継続する文脈 | worker再起動後も同じCodex会話を続けられます。通話終了後も会話は残ります。 |
| 音声と文字起こし | 許可された音声チャンネルで会話し、確定した文字起こしを通話ごとのDiscordスレッドに記録します。 |
| 質問と承認 | Codexの質問や承認要求にDiscordフォームとボタンで答え、元の要求に応答します。 |
| エージェント設定 | プロファイル名とメモリ動作を設定し、`/discodex settings`から利用可能なモデル、推論強度、権限、入力方式を選べます。 |
| 同梱Discodexスキル | インストール時に選んだ言語のガイドと、導入済みビルドに対応するセットアップ・設定・問題解決の参考文書を提供し、更新時に管理対象ファイルを更新します。 |
| メッセージ受信範囲 | `Everyone`、`RegisteredServer`、`RegisteredChannels`、`Paired`から選び、許可リストと拒否リストを管理できます。拒否リストが優先されます。 |
| Markdown表 | 完了した通常回答と`discord_send_message`の表を折り返し・ページ分割したPNG添付で表示し、インラインの太字・斜体・下線と前後の文章を保持します。ローカライズされた**原文を表示**ボタンを押すと、押したユーザーだけがMarkdown原文をページごとに確認・コピーできます。 |
| 作業の進捗 | 変更されたプランごとにホームチャンネルへ新しいEmbedカードを作り、以前のカードは編集しません。完了数/総数、完了チェックと取り消し線、進行中の矢印、未着手マーカー、状態色を表示し、同一イベントの再送は抑制し、プラン全文はDiscordの実際の上限に合わせてページ分割し、切り詰めません。CLI作業・管理ワークツリー機能もDiscordに接続します。 |
| Discordの情報と添付 | メッセージ、チャンネル、ユーザーを参照し、画像やファイルを会話に渡します。別チャンネルへの投稿は明示的な依頼に従います。 |
| Native機能 | プロファイルごとの`native-features.json`で公式app-server機能を管理します。設定画面は実効状態と保存値を区別し、再起動が必要な変更を示します。 |
| プラグイン | `/discodex plugins`で現在のnativeカタログを確認し、Discordボタンで利用可能な読み取り・インストール・アンインストールを行います。推奨と認証は公式nativeフローに従います。 |
| 非同期の質問と通知 | nativeの質問にDiscordボタンまたは自由入力で回答でき、元の質問IDとthreadに結び付きます。非同期通知は進行中turnを終了せずホームチャンネルに届きます。 |
| イベント処理とログ | メイン制御イベントは監督対象のconsumerが処理し、プロファイル別の永続ログを保存します。コンソールなしで起動するWindows GUI workerの調査にも使えます。更新はビルド済みReleaseを使います。 |

通話中、ホームチャンネルへの入力や他チャンネルでのボットメンションは受信箱に保管します。通知には投稿者、チャンネル、本文の冒頭、添付の有無を表示します。プレビューは全文取得を意味しません。音声モデルは必要な場合、または依頼された場合だけ受信箱を読みます。通話後も未処理項目は保持されます。

受信ポリシーは入力を許可するユーザー範囲を決めます。許可された入力は、ホームチャンネル、ボットへのメンション、登録チャンネルやそのスレッド、許可されたDMから既存のルーティング経路に入ります。メンション自体はポリシーを上書きしません。

通常の回答、質問、承認、進捗はホームチャンネルに届きます。ホームチャンネルの入力には元投稿への返信を付け、回答では入力投稿者への明示的なユーザーメンションを使用できます。別チャンネルに投稿するのは、宛先と送信をユーザーが明示した場合だけです。

## はじめに

[最新Release](https://github.com/CHOAM-CO/Discodex/releases/latest)から`discodex-installers.zip`をダウンロードして展開し、そのフォルダーで実行します。ReleaseにはWindows、macOS、Linux向けx64/ARM64のビルド済み実行ファイルが含まれます。スクリプトがOSとアーキテクチャに合うworkerとCodexランタイムを取得するため、Rust、Cargo、Gitは不要です。アカウント・メモリ・履歴を共有する既存Codexホーム（検出時は推奨）かDiscodex専用ホームを選び、共有設定は保持します。

```sh
./install
```

Windows PowerShellでは`./scripts/install.ps1`を実行します。インストーラーでEnglish（既定）、한국어、简体中文、日本語を選べます。選んだ言語はインストール案内、Discord UI、エージェントの基本指示に使われます。`DISCODEX_LANGUAGE=en`、`ko`、`zh`、`ja`を事前に設定すると、言語を再度尋ねません。

インストーラーはCodexとDiscordを接続し、プロファイルとユーザー単位の自動起動を設定します。移行、更新、削除の詳細は[日本語インストールガイド](docs/installation.ja.md)を参照してください。

## カスタムモデルとローカルモデル

メインモデルと**既定サブエージェントモデル**には、ネイティブカタログと明示的に登録したプロバイダー・モデルを表示します。同梱フォークでは、子が親と別のプロバイダーを利用できます。保存した子の既定値は、worker再起動後を含め、次のスレッド作成・再開時に読み込みます。現在のスレッドは再開まで有効な設定を維持し、既存の子の設定と親の会話も保持します。認証とモデル能力はCodexが管理します。例は[プロバイダー設定](docs/installation.ja.md#カスタムおよびローカルcodex-provider)を参照してください。

履歴の互換性は`encrypted_content`と`agent_messages`で独立して指定します。送信形式を変換して読める文脈を保ち、保存済み原本は変更しません。[履歴の互換性](docs/design.ja.md#プロバイダー切り替えと暗号化履歴)を参照してください。

Antigravity設定は次のモデル選択またはAGYセッション開始時に適用され、ネイティブプロセスの機能切り替えにはworker再起動が必要です。設定で **Antigravity** を有効にすると、インストール済みCLIの`agy models`から正確なモデルIDと名称を取得し、両方の選択画面に表示します。手入力IDは一覧を補足します。推論強度はCLIの`--help`から取得し、モデル名による推測や変換はしません。取得エラーは設定に表示し、明示した未対応の強度もそのままCLIへ渡して実際のエラーを受け取ります。別途インストールしたAGY CLIの既存サブスクリプションログインを使い、SDKは使いません。重複する内蔵ツールはAGY、追加のDiscord・タスクツールはMCPで接続し、子のライフサイクルはCodexフォークが管理します。応答ごとに新しいCLIへネイティブ会話と可視ツール結果を渡し、AGYの非公開状態は再開しません。AGY音声には対応しません。

## 更新

`/discodex update`は最新Releaseを直ちに確認します。**更新 / キャンセル**画面で、サブエージェントを含む進行中の作業と音声が中断されることを案内します。確認後はアイドル待ちキューなしで適用し、再起動後に完了または失敗をホームチャンネルへ通知します。中断した応答は自動再開せず、再開プロンプトや空入力も挿入しません。

自動確認は成功から6時間後、失敗から15分後です。通知は5分アイドル後に表示し、**更新**、**このバージョンをスキップ**、**今後通知しない**を選べます。時間条件は通知用で、確認済みの更新を遅らせません。

手動更新はインストーラーバンドルから実行します。

```sh
./update --config "<既存config.jsonのパス>"
```

```powershell
./scripts/update.ps1 -Config "<既存config.jsonのパス>"
```

workerと対応するビルド済みCodexパッケージを取得します。マニフェストでworkerのバージョン、フォークのコミット、プラットフォーム、チェックサムを固定します。ランタイムを先に準備し、選んだプロファイルの所有ファイルだけを置換します。置換や再起動に失敗した場合、以前のworker、プロファイル設定、ランタイム参照、所有記録、サービス状態の復元を試みます。必要な復元段階が失敗すると、その段階に依存する後続処理を止めて原因を報告し、新旧ファイルが混在した状態で再起動しません。未使用の準備済みランタイムは必要なサービス復元の後に削除し、削除の失敗も報告します。Codexホーム、アカウント、メモリ、履歴、設定は保持します。0.1.xの自己更新で使う実行ファイル名とhelper入口は維持し、0.1.3より前の版は先に手動スクリプトで更新します。クライアントでのソースビルドはありません。

## Discordコマンド

設定パネルではメインモデル、既定サブエージェントモデル、推論強度、サービス階層、権限プロファイル、承認方針、入力方式、音声を選べます。承認の既定値は **on-request** で、権限プロファイルとは独立しています。**詳細設定**にはネイティブ機能をまとめ、子モデル設定は重複表示しません。音声の変更は次の通話から反映されます。 承認の選択はプロファイルごとの`native-features.json`に保存し、共有Codex設定は上書きしません。

- `/discodex settings`：ボタンで設定を選ぶ
- `/discodex voice`：音声プロファイルを選ぶ
- `/discodex status`：会話と設定を表示する
- `/discodex voice-join channel:<許可された音声チャンネル>`：音声チャンネルに参加する
- `/discodex voice-leave`：通話を終了する
- `/discodex interrupt`：現在の応答の停止を依頼する
- `/discodex compact`：現在の会話のコンテキストを手動で圧縮する
- `/discodex update`：更新を確認して適用する
- `/discodex new`：新しい会話を開始する

音声通話を終了しても永続会話は残ります。ドキュメント：[日本語インストールガイド](docs/installation.ja.md) · [日本語の製品設計](docs/design.ja.md)
